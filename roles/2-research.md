# Роль 2 — Ресерч: промпт и качество оценки

**Твоя цель:** доказать жюри, что оценки модели совпадают с оценками человека, и поднять это совпадение.
На защите ты называешь цифру: «совпадение с ручной разметкой — N %, стоимость оценки — $X».

Код писать не нужно. Работаешь с файлами в `research/` и промптом в `cqa/evaluator.py`.

---

## Шаг 1. Ручная разметка — часы 2–6

1. Скопируй `research/labels_template.csv` → `research/labels.csv`, открой в LibreOffice или Google Sheets.
2. Читай диалоги в `research/dialogs/<id>.md` (номера реплик `[N]` совпадают с интерфейсом).
3. Разметь **14 диалогов** — вот список:
   - RU: `p1-ru-001` … `p1-ru-006`
   - KZ: `p1-kz-001` … `p1-kz-003`
   - EN: `p1-en-001` … `p1-en-003`
   - Звонки: `p4-ru-001`, `p4-ru-002`
4. Как заполнять:

| Колонка | Что писать |
|---|---|
| `01, 02, 03, 05, 07 _answer` | `Да` / `Нет` / `N/A` (N/A только где разрешено: 02, 03, 07) |
| `04_consultation_answer` | `20` / `15` / `10` / `5` / `0` / `N/A` |
| `06_dialog_answer` | `10` / `7` / `4` / `0` |
| `08_gross_answer` | `Да` / `Нет` |
| `_evidence` | номер реплики, например `12` или `12,14` |
| `_comment` | одно предложение «почему» |

**Главные правила чек-листа (не забывай):**
- Оценивается **только оператор**. Приветствие бота не засчитывается оператору.
- «Нет» — действие было нужно, но пропущено. «N/A» — только если выполнено условие неприменимости.
- Общий вопрос (тарифы, где кнопка) → идентификация `N/A`. Раскрыл данные счёта без проверки → `Нет`.
- Консультация (04) = правильно и полно ли решён вопрос. Ведение (06) = понятно ли и последовательно ли писал.
- Грубая ошибка = оскорбление / «переведи мне лично» / личный номер для платной консультации / раскрытие чужих данных.
- Порог первой реакции оператора — 3 минуты.

⏱ Норма: ~10 минут на чат, ~20 на звонок. Итого ~3 часа.

## Шаг 2. Спорные случаи — параллельно с шагом 1

Создай `research/edge_cases.md`. Каждый раз, когда сомневаешься, записывай:

```
## p1-ru-004 · 01 Установление контакта
Сомнение: оператор поздоровался, но не назвал имя — имя было только у бота.
Решение: «Нет» — представиться должен оператор в первом ответе.
```

Это самый ценный результат: каждое решение превращается в правило в промпте.

## Шаг 3. Сравнение с моделью — часы 6–14

Когда у команды есть ключ Gemini и сервер запущен (`python3 server.py`):

1. В интерфейсе открой каждый из 14 диалогов → «Оценить» (или «Оценить неоценённые» на странице Диалоги).
2. Запусти сравнение:
   ```bash
   python3 research/compare.py
   ```
   Скрипт покажет % совпадения по каждому критерию и список расхождений с объяснением модели.
3. По каждому расхождению реши, кто прав:
   - **Модель права** → исправь свою разметку.
   - **Модель ошиблась** → допиши правило в `PROMPT` в `cqa/evaluator.py` (блок «ПРАВИЛА»).
     Пиши коротко и конкретно, например:
     `10. Установление контакта: оператор должен сам поздороваться И назвать своё имя в первой реплике; приветствие бота не считается.`
   - **Неоднозначно** → запиши в `edge_cases.md` и обсуди с командой.
4. Переоцени диалоги → снова `compare.py`. Повторяй, пока совпадение не станет **≥ 80 %**.

Правило итераций: меняй промпт по одной вещи за раз, иначе не поймёшь, что помогло.

Отдельно проверь **казахский**: если KZ сильно хуже RU — добавь в промпт пример фраз на казахском
(приветствие «Сәлеметсіз бе», прощание «Сау болыңыз» и т. п.).

## Шаг 4. Цифры для защиты — часы 14–17

Передай роли 4 (защита) одним сообщением:

- % совпадения: всего и по каждому критерию (из `compare.py`);
- где модель ошибается чаще всего и почему (1–2 пункта);
- стоимость одной оценки — видна внизу панели «Оценка качества» в карточке (токены и $);
- 3 диалога для демо: обычный, с N/A, с ошибкой модели (хороший кандидат для апелляции).

## Шаг 5. Контрольный набор — час 23

Организаторы откроют новые диалоги. Возьми 3–5 из них, быстро разметь и прогони `compare.py` —
так покажем, что точность держится и на новых данных.
